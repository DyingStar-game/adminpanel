1Admin persistance : trois façons de naviguer dans les items
L'API filtre uniquement par object_type, parent_id et scenename, avec pagination. Les compteurs par type sont obtenus avec un appel page_size=1 par type connu (lu depuis les *_def.json), puis en lisant total.
On ne charge jamais tous les enfants d'un coup, seulement des pages : 8 par grappe dans le graphe, 25 par niveau dans l'arbre, 50 par page dans le tableau. Les champs UUID (pilot_uuid, components[]) deviennent des liens, chacun résolu par un GET /items/{uuid}.
Les propriétés sont regroupées par canal de synchro (zone, distance, fréquence), comme dans les définitions de props. Les clés absentes de la définition sont listées à part.
Le live est simulé par un polling toutes les 2 s sur l'objet sélectionné, et les champs modifiés clignotent. Toutes les données sont fictives et générées.
